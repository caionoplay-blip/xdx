Projeto: XDX - Mercado

Descrição: Guia de Arquitetura, Tecnologias e Fluxo de Dados

Data de Geração: Abril de 2026

1. Visão Geral do Sistema

O XDX - Mercado é um ecossistema inteligente de gestão de inventário e captura de dados focado no segmento de supermercados (B2B). A aplicação principal é construída sob uma arquitetura de "Web App Empacotado" (Hybrid Mobile App), garantindo que o mesmo código fonte atenda tanto usuários de navegadores quanto aplicativos nativos (Android/iOS).

2. Stack Tecnológico (Tecnologias Utilizadas)

A arquitetura foi escolhida para maximizar a agilidade de desenvolvimento, reduzir a manutenção e garantir alta escalabilidade.

🎨 Frontend (Interface Visual)

  • React 19: Biblioteca central para construção das interfaces (UI).
  • Tailwind CSS 4: Framework utilitário para estilização rápida, responsiva e com um design moderno.
  • Vite 6: Motor de compilação ultra-rápido para desenvolvimento e build de produção.
  • Lucide React: Biblioteca de ícones vetoriais.

📱 Mobile (Container Nativo)

  • Capacitor 6: O "motor" que transforma o site React em um aplicativo nativo para Android e iOS, dando acesso a câmera e hardware.
  • Capacitor AdMob: Plugin integrado para futura monetização via anúncios, se necessário.

🧠 Inteligência Artificial (Core)

  • Google GenAI (Gemini): Motor principal de inteligência computacional para reconhecimento ótico e análise semântica das imagens das gôndolas e etiquetas.
  • OpenAI: API secundária (fallback) e suporte lógico para processamento avançado de texto.

☁️ Backend, Banco e Infra

  • Supabase: Banco de dados Postgres em nuvem, cuidando da persistência dos dados (inventário, histórico, logs) em tempo real.
  • Vercel (Express/Node): Infraestrutura Serverless para rodar funções backend de segurança e APIs (`/api/health`, `/api/scan`).

3. Estrutura de Arquivos e Componentes

O repositório está organizado para separar claramente o código do aplicativo (Frontend) e as configurações de hardware (Mobile).

  • /src/App.tsx: O coração da interface do usuário. Contém o painel principal, a lógica de interação do usuário com a câmera e a exibição do dashboard gerencial.
  • /src/services/gemini.ts: Módulo isolado de conexão com o motor de Inteligência Artificial. Toda chamada ao Google GenAI passa por aqui para segurança.
  • /api/: Contém as funções serverless (Node.js/TypeScript) que podem rodar isoladas da interface para realizar processamentos pesados no servidor.
  • /android/ e /ios/: Pastas nativas geradas pelo Capacitor. Contêm as configurações específicas para as lojas (Google Play e App Store).
  • capacitor.config.ts: Configuração da "ponte" entre o código Web (React) e o código Nativo (Android/iOS).

4. Fluxo de Dados Operacional

Para fins administrativos, este é o caminho que um dado percorre desde o momento em que o fiscal do mercado tira uma foto até aparecer no dashboard:

1. Captura (Capacitor/React): O usuário utiliza o aplicativo XDX para fotografar a prateleira. O Capacitor acessa o hardware da câmera nativa do celular.
2. Processamento (Google GenAI): A imagem é enviada para o serviço de IA. O modelo de visão computacional varre a imagem identificando preços, nomes de produtos e etiquetas de validade.
3. Estruturação (Node/TypeScript): A inteligência retorna um texto/JSON bruto. O código formata os dados limpos, cruza os identificadores com o cadastro (caso existam) e prepara os pacotes de banco de dados.
4. Persistência (Supabase): Os dados limpos são salvos nas tabelas seguras do Supabase na nuvem.
5. Apresentação (Dashboard): A interface do painel financeiro consome os dados do Supabase e atualiza o gráfico em tempo real para os gestores.

5. Escalabilidade e Segurança

Segurança

O ambiente é protegido por variáveis de ambiente (.env). Arquivos sensíveis como chaves do Supabase, API Keys do Gemini/OpenAI e chaves de produção (xdx-production.keystore) não são enviados ao versionamento do GitHub, sendo ignorados pelo .gitignore.

Escalabilidade (Plano de Crescimento)

Por utilizar serviços gerenciados (Supabase e Vercel), a aplicação não requer gerenciamento de servidores (Linux/VPS). O banco de dados Postgres é capaz de suportar milhões de linhas de inventário. Caso a volumetria de imagens escaneadas suba substancialmente, o único ajuste necessário será realizar upgrade do plano de cota das APIs de IA (Google) e largura de banda do Supabase.
